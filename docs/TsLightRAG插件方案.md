# TsLightRAG 插件方案

## 1. 目标与结论

基于 `D:\myprog\webstorm\TsLightRAG` 的现有代码，在 DSH 中实现本地知识库与 GraphRAG 插件。复用文档解析、分块、图谱抽取、索引、检索和相关页面，替换原工程的独立模型配置与应用外壳。

**结论：技术上可行，属于中等偏上的插件化改造，不能直接打包现有独立应用。** 当前 DSH 已提供文本模型调用、工具注册、界面插槽、设置、凭据和跨端通信等扩展点。向量及可选重排能力需要由插件补充。

本方案最初基于源码只读分析形成。2026-10-27 按后续开发指令在插件工程实施；实现范围、已运行的集成检查及未覆盖的桌面实机场景见 [开发验收记录](TsLightRAG插件开发验收.md)。设计约定不等于全部场景已取得验收结果。

## 2. 实施边界

- 所有新增代码、配置、文档、测试和构建调整均在 `trs-aip-harness-plugins/` 内完成。
- `deepseek-harness/` 仅用于读取公共 API、类型和实现参考，不修改、不生成或更新其中的文件。
- 最初方案阶段仅编写文档；后续开发阶段按用户新指令建立 `feat/tslightrag-plugin` 分支，只在插件工程安装依赖、实现和验证。TsLightRAG 源工程仍只读。
- 后续实现采用插件侧扩展和适配。如果遇到必须修改主体工程的情况，应先说明阻塞点并寻找替代方案。

## 3. 功能范围

插件业务菜单只保留以下四项：

| 菜单 | 复用入口 | 功能范围 |
| --- | --- | --- |
| 知识问答 | `apps/web/src/KnowledgeChat.tsx`、`apps/server/src/chat/service.ts` | 独立知识库对话、追问、流式回答、停止生成、对话记录和来源引用 |
| 检索预览 | `apps/web/src/QueryPreview.tsx`、`apps/server/src/retrieval/service.ts` | naive、local、global、hybrid、mix 五模式检索，证据、上下文与提示词预览 |
| 知识图谱 | `apps/web/src/GraphViewer.tsx`、`apps/server/src/graph/browse.ts` | 实体和关系搜索、邻居展开、目录分页、属性与来源查看 |
| 文档 | `apps/web/src/Documents.tsx`、`apps/server/src/documents/service.ts` | 文件或文本导入、解析与索引状态、任务取消与重试、文档删除和重新索引 |

移除 TsLightRAG 的“工作台”“模型设置”“关于”业务入口。向量和重排配置放入 DSH 插件设置，不增加第五个业务菜单。

现有 `App.tsx` 启动检查和 `Documents.tsx` 仍依赖模型设置接口，移除页面时必须同时替换这些依赖，不能只隐藏导航。

复用本地解析能力：TXT、Markdown、HTML、CSV、JSON、带文本层的 PDF，以及 DOCX、XLSX、PPTX。扫描 PDF 的 OCR 不属于本方案已具备的能力。

## 4. 界面布局

### 4.1 右侧知识库面板

保留 DSH 中间的主对话界面，在右侧栏提供“知识库”入口，内部使用四个标签承载上述功能。

| 区域 | 设计建议 |
| --- | --- |
| 面板顶部 | 显示当前 DSH 对话的知识库启用状态和控制项 |
| 知识问答 | 保留独立的知识库问答，用于直接查询和验证知识库效果 |
| 检索预览 | 查看命中证据、位置、来源及检索参数 |
| 知识图谱 | 默认展示局部图、实体属性和来源，支持扩大查看 |
| 文档 | 文档列表、导入入口、索引状态和任务操作 |

文档与检索预览适合侧栏。图谱在窄面板中容易拥挤，建议提供“展开”操作，临时切换到较大的主面板；具体侧栏和主面板联动需在实现时验证。

当前 DSH 的右侧标签注册机制可作为接入基础，主面板可通过 `main` 插槽扩展。`ui-sidebar-terminal` 和 `ui-plugin-manager` 的实现分别可作为右侧标签与主面板接入参考。

### 4.2 两种问答入口的关系

- **中间 DSH 对话**：由 DSH 智能体调用插件检索工具取得证据，再由 DSH 当前文本模型生成回答。
- **右侧知识问答**：独立知识库对话，复用 TsLightRAG 的问答流程，但文本模型同样通过 DSH 调用。

两者共享知识库数据，分别管理各自的对话状态。第一版不自动同步双方历史。

### 4.3 DSH 风格与主题跟随（必须实现）

原 TsLightRAG 的业务能力可以复用，但界面必须调整为 DSH 风格。按钮、输入框、标签、列表、分页、弹窗、提示、空状态、加载状态及问答内容应优先使用 DSH 已有公共组件和排版规范；没有合适组件时，在插件内使用宿主设计令牌实现。

必须同时跟随两类用户选择：

- **风格主题**：例如主题管理器中的“DeepSeek Harness 原版”“中国警察”，以及后续通过统一令牌接入的主题包。
- **显示模式**：DSH 当前的浅色、深色及跟随系统设置，以宿主实际解析出的模式为准。

插件不提供独立主题选择，不保存与 DSH 冲突的主题状态。用户切换风格或显示模式后，已打开的知识库面板应即时更新，无需关闭面板或刷新页面，并保留当前会话、检索结果、图谱探索状态和任务进度。

实现约束：

1. 替换原 `apps/web/src/style.css` 的独立配色、页面外壳和全局选择器，样式限定在插件组件内，避免影响 DSH 中间对话及其他插件。
2. 背景、文字、边框、按钮、交互状态和语义状态使用 DSH 公共 CSS 变量，例如 `--dsw-alias-bg-layer-1`、`--dsw-alias-label-primary`、`--dsw-alias-border-l2`、`--dsw-alias-brand-primary`。字体和字号遵循宿主设置，不固定为原工程的独立字体体系。
3. 使用宿主令牌继承风格包覆盖，不依赖“中国警察”等具体主题名称、私有颜色变量或组件 DOM 结构。当前中国警察主题已覆盖通用 DSH 令牌，可通过这一方式自然适配。
4. 常规 DOM 与 SVG 元素优先通过 CSS 变量及 `currentColor` 着色。需要 JavaScript 绘制的图形读取有效令牌并在相关变化后更新；DSH 显示模式与主题快照使用 `ctx.theme.getTheme()` 和 `theme/change`，风格包的 CSS 覆盖变化应另行确认能触发重绘，不能假定它们均产生同一事件。
5. 图谱的节点、边、标签、选中、高亮及背景都必须适配主题。类别配色在浅色和深色下保持可读，并配合文字、形状或线型区分，避免只靠颜色表达状态。
6. 弹窗、下拉菜单等 Portal 内容使用 DSH 公共浮层组件，或显式保留插件样式作用域并继承宿主令牌，避免弹出层仍显示原工程风格。
7. 右侧面板、扩大后的图谱主面板、来源预览、Markdown 与代码块均适用上述要求。主题变化不重新执行检索、索引或模型调用。

第一版视觉验收覆盖“原版 / 中国警察”与“浅色 / 深色”的四种组合，检查面板打开时切换、首次加载、图谱扩大查看、弹窗及主题停用后恢复原版。后续主题只要遵循公共令牌契约，插件应继承其样式；特殊装饰效果不承诺无需适配即可复制。

## 5. 模型配置与调用

### 5.1 配置分工

不沿用 TsLightRAG 独立的模型设置文件、模型编辑页面和密钥存储。模型职责划分如下：

| 模型角色 | 配置来源 | 调用方式 |
| --- | --- | --- |
| 问答生成 `query` | 知识库设置选择的 DSH 文本模型，默认跟随 DSH | 通过 DSH LLM 服务调用 |
| 图谱抽取及摘要 `extract` | 复用知识库选定的文本模型 | 通过 DSH LLM 服务调用 |
| 检索关键词提取 `keyword` | 复用知识库选定的文本模型 | 通过 DSH LLM 服务调用 |
| 向量化 `embedding` | 插件提供配置项，接入 DSH 设置体系 | 插件提供向量调用能力，建库和检索必需 |
| 重排 `rerank` | 插件提供配置项，接入 DSH 设置体系 | 插件提供可选重排调用，第一版默认关闭 |

中间对话的最终回答使用该 DSH 对话当前选择的模型。插件独立问答及后台索引任务使用“设置 → 知识库 → 文本模型”的选择：默认跟随 DSH，也可固定一个 DSH 已配置的模型。跟随 DSH 读取 `agentDefaultModel.currentSelection()`；当前 DSH 会在中间对话切换模型后后台保存默认选择，并无单独的“默认文本模型”设置项。固定选择只保存 provider/model，复用 DSH 服务与凭据，不受聊天切换影响，也不改变 DSH 默认模型。任务保留配置版本检查；任务中途修改可能需手动重试。固定模型不可用时明确失败，不自动回退。

当前源码中的 `agentDefaultModel.currentSelection()`、`llm.prepareCall()` 及流式调用可作为文本模型适配基础。本次检查的 DSH 模型接口中未发现统一的 embedding、rerank 服务，不能将聊天模型配置视为向量服务配置。

### 5.2 插件自行配置的含义

“插件自行配置”是由插件声明和维护向量、重排配置项，但保存、编辑和凭据管理仍接入 DSH：

- 在 DSH 插件设置中编辑，不单独保留 TsLightRAG 模型设置页面。
- 配置中保存凭据引用，密钥交由 DSH Credentials 管理。
- 密钥不返回浏览器，不写入知识库历史快照。
- 复用原工程必要的协议校验、超时、取消、批量处理和错误处理行为。

建议配置字段：

| 配置 | 建议字段 |
| --- | --- |
| 向量服务 | 接口地址、模型名称、凭据引用、向量维度、批量大小、超时 |
| 重排服务 | 启用状态、接口地址、模型名称、凭据引用、返回数量、超时、失败策略 |

协议支持以实际适配和验证结果为准，第一版可沿用 TsLightRAG 当前的 OpenAI 兼容向量协议和既有重排协议。

### 5.3 模型适配与索引一致性

原 `models/config.ts` 同时管理配置版本、任务版本校验、活动向量绑定和向量空间身份，不能直接删除后只读取 DSH 当前配置。

插件需要建立自己的适配接口，替换业务逻辑对 `ModelClient`、`ModelConfigStore`、`PrivateProfile` 的直接依赖。保留必要的任务配置快照、模型身份、版本和配置指纹，配置与凭据来源统一改为 DSH。

必须遵守以下规则：

1. 向量索引记录生成它的模型、维度和空间身份等必要元数据。
2. 查询必须使用与活动索引兼容的向量配置，不能用新向量模型直接搜索旧向量库。
3. 更换向量模型、维度或影响向量空间的配置后，需完整重建索引。
4. 重建完成前，保持旧索引一致可用；旧服务已不可用时，应明确提示需要重建。
5. 不依靠复制旧密钥保存历史配置；凭据失效或配置无法解析时明确失败。
6. 更换重排模型通常不需要重建向量索引，但应使相关查询缓存失效。
7. 原工程虽然保留完整重建接口，但当前文档页面没有向量切换入口，插件需要补充明确的重建入口与状态提示。

## 6. 中间 DSH 对话使用知识库

### 6.1 检索工具流程

插件向 DSH 注册知识库检索工具，建议名称为 `knowledge_search`，具体名称在实现时确定。

流程如下：

1. 用户在当前 DSH 对话启用知识库。
2. DSH 根据问题决定是否调用知识库检索工具。
3. 插件执行关键词提取、向量与图谱检索，以及按配置启用的重排。
4. 工具返回预算内的证据文本、文档名称、文档及块标识、原始位置和引用信息。
5. DSH 当前模型基于证据生成最终回答，并按提示要求标明来源。

该工具应复用检索能力，避免调用插件的完整问答流程，防止重复生成回答。图谱检索中的关键词提取等步骤仍可能调用文本模型。

工具只能检索当前授权范围内的数据。关闭知识库时，既不向模型声明工具，也不允许执行新的检索。执行端还需检查启用状态，防止已准备步骤中的旧工具调用绕过关闭操作；已开始的检索应按取消策略处理。

### 6.2 可选择的使用模式

| 模式 | 行为 | 阶段建议 |
| --- | --- | --- |
| 关闭 | 当前对话不能发起新的知识库检索 | 第一版 |
| 自动使用 | 向当前对话开放检索工具，并注入会话级提示，要求资料性问题优先检索知识库；具体调用仍由 DSH 模型执行 | 第一版 |
| 每次检索 | 每次发送问题先检索，再结合证据回答 | 后续增强，需验证发送或模型请求前的扩展点 |

DSH 的 `ctx.tools.register(..., { when })` 支持按当前 Agent 条件启用工具，可作为“关闭 / 自动使用”的实现基础。仅开放工具不保证模型每次调用，不能将“自动使用”描述为强制检索。

第一版建议默认关闭，按当前 DSH 对话保存选择。插件维护会话级状态，通过 Host 端服务保存和查询，浏览器开关经 DSH Remote 更新；具体存储及会话清理联动需实现时确定，不假定 DSH 已有该字段。

右侧面板显示“作用于当前 DSH 对话”，中间对话标题附近可通过现有会话操作插槽补充“知识库已启用”状态。切换会话时同步读取对应状态，避免跨会话误用。

### 6.3 关闭与引用的边界

关闭知识库会停止新的检索，但不会从 DSH 历史上下文中自动移除已经返回的知识库证据。需要完全排除历史证据时，应新建对话并保持关闭。

插件可提供文档来源导航，但中间 DSH 回答中的引用形式及点击联动需要另外适配和验证，不能仅凭返回文档标识就保证完整的可点击引用体验。未找到证据时，应明确反馈，不将模型常识表述为知识库结论。

## 7. 插件架构

采用包含 Host 和 Client 的原生双端插件，建议目录如下，名称为暂定：

这里的“双端”指同一个本地插件包内的“界面层 + 本地后台层”，由 DSH 加载和管理，不要求独立部署服务器或由用户分别启动两个应用。文档解析仍可使用本地 Worker，避免阻塞宿主。

```text
trs-aip-harness-plugins/
  packages/
    knowledge-rag/
      src/
        index.ts          # Host 插件入口
        client/           # 右侧面板、四个功能标签、扩展主面板
        models/           # DSH 文本适配、向量及重排调用
        documents/        # 导入与任务管理
        parsers/          # 本地解析及 Worker
        indexing/         # 抽取、合并与索引维护
        retrieval/        # 检索及证据预算
        storage/          # 本地快照与知识库数据
        tools/            # DSH 知识库检索工具
        remotes/          # 跨端契约和服务
```

| 层次 | 职责 |
| --- | --- |
| Host | 文档解析、分块、抽取、索引、检索、任务调度、存储、设置和凭据接入 |
| Client | 四个功能标签、当前对话开关、图谱扩大查看、状态及引用导航 |
| Remote | 文件传输、查询、流式结果、取消、任务状态与会话启用状态 |
| Tool | 将知识库证据提供给中间 DSH 智能体 |

优先通过 DSH Remote 调用业务服务，不强制启动独立 Fastify 服务。如果上传或流式传输需要额外宿主通道，需单独验证权限、取消和桌面兼容性。

数据放在独立插件数据目录，明确按 DSH Profile 或知识库隔离；不写入源码目录。第一版可先实现单知识库，不将多知识库选择列为已确定需求。Host 卸载时应取消活动任务、停止 Worker 并释放文件锁。

不推荐将原应用直接作为 iframe 嵌入：现有响应设置了 `frame-ancestors 'none'`，且依赖独立 HTTP 服务、根路径路由和独立模型配置。原生插件更符合本方案的模型复用和中间对话联动目标。

| 改造项 | 现状与处理方向 |
| --- | --- |
| 应用外壳 | 替换 `App.tsx` 的独立导航、状态检查和启动流程，注册 DSH 侧栏标签和主面板 |
| 前端请求 | 替换 `/api/v1/...` 硬编码请求，接入插件通信接口 |
| 页面导航 | 替换 `/documents`、`window.location` 和浏览器历史操作，接入面板内导航 |
| 文本模型 | 适配 DSH 消息、文本及思考分离、流式事件、终止原因、取消与 token 预算 |

| React | TsLightRAG 使用 React 19，当前 DSH 渲染器使用 React 18，需统一宿主运行时并验证组件兼容性 |
| 风格与主题 | 将原工程样式改为 DSH 公共组件及语义令牌，跟随风格主题、浅色/深色和字体设置；包含图谱、浮层和展开面板 |
| Worker 与资源 | 打包解析 Worker、PDF 资源、分词资源及动态加载文件，验证发布后路径 |
| 原生模块 | 验证 `fs-ext-extra-prebuilt` 在实际 DSH Host 运行时的 ABI 和打包兼容性 |
| 权限与生命周期 | 通过宿主端鉴权与会话绑定，正确处理插件卸载、任务取消、重启和文件锁 |

## 9. 限制与待验证事项

- 当前向量检索遍历内存中的向量，适合先定位为本地、有限规模知识库；大规模使用需要专项性能评估。
- 原工程使用本地完整快照，历史 generation、解析产物等会占用额外空间，需明确容量提示、备份和后续清理策略。
- 文件系统单写者约束必须保留，不支持多个进程同时写同一个数据目录。
- 原工程文档记录了 Linux 验收结果；跨平台说明中 Windows 仍未取得实机验证结果，不能视为 DSH Windows 桌面集成已验证通过。
- 插件调用真实模型后的抽取质量、检索效果、上下文预算和流式协议需要实测。
- 当前图谱为有限范围浏览，不应将无限全图、任意编辑、拖拽和缩放视为已有功能。
- TsLightRAG 提供 MIT 许可及第三方归属文件，复用与发行时需保留相应许可证和资源声明，按实际打包依赖更新归属材料。

## 10. 实施阶段与验收

### 阶段一：宿主适配与最小闭环

- 建立插件包、Host 生命周期、Remote 契约和独立数据目录。
- 接入 DSH 文本模型和 Credentials，提供向量配置；重排默认关闭。
- 完成文档导入、解析、索引、检索、来源查看与重启恢复。
- 验证实际 Host 运行时中的 Worker 和原生文件锁。

### 阶段二：右侧四项功能

- 接入知识问答、检索预览、知识图谱和文档标签。
- 完成任务状态、取消重试、删除、重新索引和跨页来源导航。
- 提供图谱扩大查看和向量变更后的完整重建入口。
- 完成 DSH 风格重构与主题即时跟随，验证原版、中国警察主题的浅色和深色组合。

### 阶段三：中间 DSH 对话联动

- 注册知识库检索工具。
- 实现按 DSH 对话控制的“关闭 / 自动使用”，默认关闭。
- 实现启用状态提示、证据预算和来源展示。
- 验证会话隔离、关闭后的执行拦截及历史上下文边界。

### 阶段四：发行与增强

- 完成 DSH Windows 桌面和适用 Web 场景的集成验证。
- 验证可选重排、插件启停、配置变更、故障恢复与发行资源完整性。
- 根据扩展点验证结果决定是否增加“每次检索”。

主要验收条件：

1. 所有实现都位于插件工程，主体工程无修改。
2. 业务菜单仅有四项，DSH 中间对话继续可用。
3. 文本模型复用 DSH，向量与重排配置位于 DSH 插件设置，密钥不回传浏览器。
4. 文档导入、索引、问答、图谱及来源跳转形成闭环。
5. 向量配置变更不会混用新旧空间，重建失败不会替换有效旧索引。
6. 中间对话可按会话选择是否使用知识库，关闭后不能发起新检索。
7. 流式取消、任务中断、重启恢复和插件卸载正确释放资源。
8. 通过真实插件装配与运行测试验证，不仅依靠单元测试或原工程既有报告。
9. 四项功能及全部浮层、来源预览和图谱展开面板遵循 DSH 风格；切换风格主题及显示模式后即时更新，不丢失业务状态或额外触发模型调用。
