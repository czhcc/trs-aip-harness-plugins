# TsLightRAG 插件开发与验证记录

日期：2026-10-27。开发分支：`feat/tslightrag-plugin`。

## 实现范围

新增 `packages/knowledge-rag/`，包名为 `@trs-aip/dsh-knowledge-rag`，版本为 `0.1.0`。实现采用同一个插件包中的 Host、Client 和解析 Worker，不启动独立 HTTP 服务。所有源码、依赖清单、构建和测试产物均在插件工程内；`deepseek-harness/` 与 TsLightRAG 源工程只读。

| 方案要求 | 实现 |
| --- | --- |
| 右侧四项功能 | 知识问答、检索预览、知识图谱、文档；面板展开及来源跳转 |
| 知识问答 | 独立历史、追问、流式回答、停止、删除与来源展示 |
| 检索预览 | naive/local/global/hybrid/mix；证据、上下文、提示词和诊断；可选重排 |
| 图谱 | 实体/关系目录、搜索、分页、邻居展开、属性和来源；有限节点布局与扩大查看 |
| 文档 | 文件与文本导入、解析预览、索引状态、取消、重试、删除和重新索引 |
| 索引维护 | 完整重建、任务状态、取消和重试；失败保留旧索引；清理状态展示 |
| 文本模型 | 在知识库设置中跟随 DSH 或固定已配置模型；问答、关键词和图谱抽取复用该选择；区分正文与思考，处理取消和不完整响应 |
| 向量及重排 | DSH 插件设置声明配置，凭据由 DSH Credentials 保存；不保留原工程模型编辑页面 |
| 索引一致性 | 保存不含密钥的模型身份、配置版本和凭据引用；旧索引使用原向量配置，切换空间须重建 |
| 中间对话 | 标题及侧栏提供当前会话的“关闭/自动使用”，默认关闭；通过 `knowledge_search` 返回证据，由 DSH 当前模型作答 |
| 权限 | Remote 同时验证 profile 全局访问与目标会话访问；工具执行时再次验证会话开关 |
| 主题 | React 18 宿主运行时，公共设计令牌、Button、Modal；SVG 和 Markdown 随主题变化，切换不重新检索 |
| 发行接入 | 工作区构建、验证脚本、桌面 profile、插件打包清单及版本替换逻辑已接入第五个插件 |

## 关键代码

- `packages/knowledge-rag/src/index.ts`：Host 注册、权限与工具。
- `src/runtime.ts`、`src/remote.ts`：业务装配、任务、上传、取消与跨端契约。
- `src/models.ts`、`src/settings.ts`：DSH 模型适配、配置与凭据引用。
- `src/engine/`、`src/contracts/`：迁移后的 TsLightRAG 解析、快照、索引、图谱与检索核心。
- `src/client/`：四个功能标签、会话开关、设置及主题样式。
- `third_party/`：上游 MIT 许可、来源说明、原资源归属与浏览器内置依赖许可证。

以上 `src/` 与 `third_party/` 均相对于 `packages/knowledge-rag/`。

## 已运行验证

环境为 Windows x64、Node.js 24.19.0、本地 DSH `0.2.1-rc.3` 接口与 React 18。浏览器测试使用本机 Microsoft Edge。

1. 五个插件 TypeScript 检查、构建，以及仓库清单验证。新增插件额外检查 Host 语法、Client 外部模块白名单、Worker 和动态解析文件完整性。
2. 使用真实 DSH Loader、LLM Runtime、DefaultModel、Tools、Typert Gateway 和 RemoteAccess 装配生成的 Host 产物。通过网关执行文档导入、索引、图谱、检索、重排、流式问答、重建、重启与卸载；验证 SRC-JSON 输入输出、访客拒绝和会话隔离。
3. 验证默认关闭、会话启用、关闭后的旧工具执行被拦截；验证向量切换仍使用旧索引的配置、重建失败保留旧索引、重试后切换；验证模型元数据不含测试密钥。
4. 验证缺少模型配置时仍能解析文档并进入等待配置状态；校验非法维度和嵌入账号密码的接口地址；验证仅有思考内容时不会伪造正文回答。
5. 使用打包后的 Worker 解析 TXT、Markdown、HTML、CSV、JSON、PDF、DOCX、PPTX、XLSX；拒绝无文本层及加密 PDF。
6. 浏览器加载构建后的真实 Client factory 和宿主公共组件，验证四个标签、解析预览、安全 Markdown、来源导航、图谱展开、设置保存、确认弹窗及卸载样式清理。
7. 原版/中国警察 × 浅色/深色四种组合现场切换，检查颜色变化、业务状态保留及没有新增检索。截图位于本包忽略目录 `.test-data/browser/`。
8. `npm pack` 后在独立目录解包，再运行 Host 集成测试与全部格式解析测试，验证发布目录中的 Worker、动态文件和原生文件锁路径。

测试中的文本模型使用确定性 DSH 适配器，向量与重排使用本地测试接口；Credentials 与设置持久化服务使用测试实现。浏览器使用真实插件与公共组件，但由测试外壳模拟侧栏、插槽、配置和远程服务。网关测试为进程内调用，不包含真实 WebSocket 传输。这些结果不等于完整桌面应用已经通过实机验收。

## 复现方式

先在插件仓库安装工作区依赖；开发依赖通过 `link:` 只读引用同级 DSH 的已有公共包。本机 pnpm 完整安装的文件导入阶段长时间停滞，验证时使用已下载且版本匹配的本地依赖建立链接，并完成锁文件解析；尚未验证干净网络环境中的完整安装流程。

```powershell
# 插件仓库根目录
pnpm typecheck
pnpm build
node scripts/validate.mjs

# packages/knowledge-rag 目录，构建后
$env:RAG_BROWSER_CHANNEL='msedge'
pnpm test
npm pack --ignore-scripts --pack-destination .test-data
node tests/packed.mjs
```

本机为避开 pnpm 安装检查和 PowerShell 脚本策略，实际检查使用 `node` 直接执行已安装的 TypeScript、tsdown、tsx 与测试脚本；未在主体工程运行构建或安装。压缩包测试复用本地依赖链接，不进行网络安装。

## 使用与数据

新建空白会话的知识库开关已接入公共 `conversation.hero.options` 扩展点（2026-10-27），与已有会话标题栏复用同一组件和会话 ID；无需先发送消息。无会话 ID 的初始页面不渲染该宿主扩展点，选择工作区创建会话后显示。Client 激活测试覆盖两个位置的注册；构建后的浏览器测试覆盖空白会话切换、进入标题栏后保留状态、另一会话默认关闭及返回原会话关闭。完整类型检查、构建、Host 集成与浏览器回归通过；未修改主体工程。

安装并启用插件 bundle，在 DSH 配置服务商和文本模型，然后在“设置 → 知识库”选择文本模型并填写向量接口、模型、维度及所需凭据；重排默认关闭。文本模型默认跟随 DSH 最近保存的选择，也可固定，仍复用 DSH 的服务与凭据。向量地址采用 OpenAI 兼容 Base URL，重排配置完整接口 URL。导入文档后可在右侧检索或问答；中间对话须显式切换为“自动使用”。自动模式由模型决定是否检索，不保证每次调用工具。

数据位于当前 profile 的 `data/trs-aip-knowledge-rag/`。目录包含原文、解析产物、索引快照、独立问答记录和会话开关，应整体备份，且仅允许一个 Host 写入。更换向量空间后完整重建；凭据失效不能通过历史快照恢复密钥。

## 尚需实机场景验证

### Web 激活兼容性修复（2026-10-27）

实际 Web 启动发现 Client 激活失败。真实 Client Gateway 回归测试复现原因为 `client api: generated Remote trsAipRag/request field "request" has no strict codec`：请求参数只声明 SRC-JSON，而浏览器网关要求严格校验器。已将请求描述改为带 Zod schema 的 strict codec，并让 Host 复用同一请求 schema；返回值仍为 SRC-JSON。新增测试加载构建后的 Client factory，经过真实 Client Gateway 挂载和请求，并验证卸载清理；原实现下失败，修复后通过。该测试同时加入压缩包解包验证。

Host 闭环、多格式解析及四种主题浏览器测试重新通过。尝试刷新用户的 Web 页面时，`127.0.0.1:3080` 已停止服务，因此当前完整 Web 实例的重新启动与页面验收仍需继续确认。

### 知识库文本模型选择（2026-10-27）

新增“设置 → 知识库 → 文本模型”，通过 DSH 公共 `session.modelCatalog()` 读取服务商分组列表，支持刷新、加载失败提示、保留已保存的不可用模型，以及默认的“跟随 DSH”。固定选择仅保存 provider/model 标识；复用 DSH 的调用与凭据体系，不改变中间对话模型或 DSH 默认值。旧配置没有 text 字段时自动跟随 DSH。

真实 Loader/Gateway 集成测试验证：固定模型后改变 DSH 默认选择，知识库调用仍进入固定模型；恢复跟随后采用新默认选择；固定服务商不可用时返回错误且不回退；配置热更新不重挂载插件；重新装配后采用保存的固定配置。浏览器测试验证按服务商选模型、保存与重新打开保留选择、目录加载失败保留选择、恢复跟随并保存。保留原有向量空间一致性、Worker 和主题测试。

### 图谱初始空白修复（2026-10-27）

原页面只初始化实体目录，关联图需要搜索或手动选择后才加载；空图点击刷新也只刷新目录，因此即使后端有实体仍会显示空白。已改为进入图谱标签时自动加载最多 100 个初始实体及其范围内关系；隐藏标签不提前加载；已探索的非空关联图在切换标签时保留。空图刷新同样加载初始图，新增加载、无实体、无匹配节点和截断提示。重新进入之前为空的图谱会再次加载，以便看到新建库的数据。

浏览器回归测试验证无需点击搜索即可出现节点、清空后刷新恢复、空索引提示，以及索引由空变为非空后切回标签自动加载。修复不执行模型调用，也不修改或重建已有索引。

### 自然提问的知识库引导（2026-10-27）

实际使用发现：明确写出 `knowledge_search` 时可检索，自然提问时模型可能只搜索工作区文件，进而错误声称没有资料途径。原实现只开放工具，未贡献会话级知识库可用性提示。已增加 DSH `systemPrompt.context` 动态上下文：仅对开启知识库且工具可见的会话，要求人物、奖项等资料性问题优先检索知识库；解释知识库独立于工作区，要求基于文档证据回答并引用，区分检索失败与未命中，并将资料正文作为证据而非指令。工具描述同步补充使用场景。

上下文声明为 required，可在宿主每次请求的上下文刷新阶段更新，适用于已打开的会话；开关关闭后返回空文本，不向其他会话泄露启用状态。没有改变用户的其他工具权限，也没有实现发送前强制检索。

真实 Host 集成测试验证开关前后、不同会话、无 Agent、已准备步骤及请求上下文刷新时的提示内容，并实际执行工具检查证据与文档来源。构建和依赖锁文件校验通过。尚未用真实模型重跑用户原始自然问句，因此不能把提示注入测试视为所有模型均会自动调用的保证。

### 剩余验证范围

- 完整 DSH 桌面应用中的安装、启停、真实 Settings/Credentials 持久化和 WebSocket 权限传输，以及实际 Host/Electron 运行时的原生模块 ABI。
- 使用目标厂商真实模型，验证图谱抽取质量、检索效果、token 预算、流式协议和费用。自动测试不调用个人模型账号。
- 干净环境依赖安装、桌面安装器构建和签名，以及原生依赖随安装器再分发时的许可证清单复核。
- 大语料量、长时间运行、磁盘容量和恢复压力测试。向量检索仍为内存扫描，未承诺大规模性能。

第一版为每个 profile 一个知识库；没有强制每次检索、多知识库管理、OCR、无限全图编辑或中间对话引用的专用可点击组件。中间对话关闭后，已有历史证据不会自动删除；需要完全排除时应新建关闭知识库的对话。
